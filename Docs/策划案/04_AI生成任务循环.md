## 1. 一句话定位

玩家与治安官 Agent 对话 → 结构化任务 → 场景内完成 → 交还领奖 → 写 Memory → 生成下一环；第 3 环结束后打开矿洞 Boss，把 02 接进主线。

---

## 2. 体验目标

| 项 | 内容 |
|----|------|
| 幻想 | 西部风小镇，治安官/酒馆老板给你「活」 |
| 单次会话 | 连续完成 3 环任务即算 Demo 通关 |
| 单环时长 | 2～5 分钟 |
| 失败 | 任务放弃或目标 NPC/物体被破坏（可选） |

---

## 3. 设计原则（策划不熟时先记住这 5 条）

1. **AI 只生成「任务意图」，不直接改玩法数值权威**  
   AI 输出结构化任务 → 游戏逻辑校验 → 合法才接取。  
2. **任务必须可验证**  
   每个任务有明确完成条件（杀 N 只、交 M 个道具、到达点、对话某人）。  
3. **上下文要短而硬**  
   发给模型的是摘要（上次任务、结果、玩家物品摘要），不是全文聊天记录。  
4. **永远有降级方案**  
   API 失败 / 解析失败 → 用心跳模板任务表兜底，保证 Demo 可玩。  
5. **Server 权威**  
   接取、进度、提交、发奖只在 Server；AI 请求可由 Server 发起。

---

## 4. 核心循环（正式流程）

```
[对话中]
玩家：接活 / 闲聊
  → DialogueService 组上下文
  → QuestAgent.Generate(QuestSpec JSON)
  → QuestValidator 校验（目标类型、数量上限、物品是否存在）
  → 通过：QuestManager.Accept
  → UI 显示任务追踪

[玩法中]
世界事件（击杀/拾取/进入区域/交互）
  → QuestManager.NotifyProgress
  → 目标完成 → 状态变为 ReadyToTurnIn

[提交]
玩家对 NPC 提交
  → Server 校验完成度
  → RewardService 发奖（走 Demo03 背包）
  → 写 Journal 摘要进 Memory
  → 自动或手动触发下一环 Generate
```

## 5. 任务规格（QuestSpec）——AI 必须输出的结构

```json
{
  "questId": "auto",
  "title": "清剿郊狼",
  "brief": "酒馆老板抱怨狼群靠近马厩。",
  "objectives": [
    {
      "type": "Kill",
      "targetId": "Enemy_Coyote",
      "count": 3,
      "description": "击杀郊狼"
    }
  ],
  "rewards": [
    {"type": "Item", "itemId": "Ore_Iron", "count": 5},
    {"type": "Currency", "id": "Gold", "count": 20}
  ],
  "tags": ["combat", "early"],
  "failure": "AbandonOnly"
}
```

### 5.1 目标类型（Demo 只做这 4 种）

| type | 完成条件 | 世界钩子 |
|------|----------|----------|
| Kill | 击杀指定 Id 累计 N | AI/GAS 死亡事件 |
| Collect | 背包持有某物 N | 拾取/制造 |
| Reach | 进入 Trigger | Volume BeginOverlap |
| TalkTo | 与指定 NPC 交互 | Interact |

### 5.2 校验规则（防 AI 胡说）

- `count` 上限：Kill≤10，Collect≤20  
- `targetId` / `itemId` 必须存在于 Content Registry  
- 奖励总价值不超过当前环索引预算  
- 禁止生成「无法到达」的 Reach（目标点需在白名单）  
- 同一 `targetId` 连续 3 环重复 → 驳回并重滚或换模板

## 6. Agent / 上下文设计

### 6.1 角色设定（System Prompt 要点）

- 你是西部小镇任务经纪 / 治安官助手  
- 只输出 JSON（或 JSON 代码块），不要废话  
- 任务要符合西部题材与当前世界状态  
- 难度随 `ringIndex` 轻微上升  

### 6.2 上下文包（每次生成带上）

| 字段 | 来源 |
|------|------|
| ringIndex | 1/2/3 |
| playerSummary | 等级、武器、关键物品（截断） |
| lastQuest | 上一环 title + 结果 Success/Fail |
| worldFlags | 如 `WolvesCleared=false` |
| bannedTargets | 最近用过的目标 |

### 6.3 Memory（短期）

用 `UQuestJournalSubsystem` 存：

- 已完成任务摘要列表（最多 10 条）  
- 当前环数  
- NPC 好感（可选，0～100）  

**不要**把完整 LLM 对话历史无限追加；摘要化即可。

| 模式 | 用途 |
|------|------|

## 13. 验收清单

- [ ] Mock 模式下稳定打通 3 环，不依赖外网  
- [ ] AI/模板输出非法字段时被 Validator 拒绝并降级  
- [ ] 进度只在 Server 统计，客户端伪造完成无效  
- [ ] 提交后奖励进背包（或占位货币）且 Journal 更新  
- [ ] 对话 UI 能展示任务 brief 与完成态  
- [ ] 能讲清：结构化输出、校验、降级、上下文摘要、权威服

## 14. 面试口述提纲（建议背熟）

1. **为什么不全用自然语言当任务？** → 不可验证、难存档、难反作弊。  
2. **Agent 放哪？** → Server 侧服务，客户端只显示。  
3. **和传统任务表比的价值？** → 同框架下内容组合空间大；但仍需设计约束与预算。  
4. **失败怎么玩？** → 降级模板，保证核心循环不断。  
5. **上下文爆炸？** → 摘要 Memory + 白名单世界状态。

## 15. 风险与边界

| 风险 | 对策 |
|------|------|
| 模型延迟 | UI 显示「构思任务中…」；超时用模板 |
| 胡编物品 | Registry 白名单 |
| 玩家刷任务 | 环数上限、奖励预算、冷却 |
| 题材跑偏 | System Prompt + 后置 Tag 过滤 |
