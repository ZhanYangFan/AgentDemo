## 1. 一句话定位

大厅 UI：公会社交页 + 商城/战令/活动的协议驱动数据流；玩法内获得的成长在这里展示与消费。

---

## 2. 为什么要做这一层

战斗/AI/背包证明 Gameplay；大厅证明你能讲清 **强 UI、强协议、强联调、强商业化客户端**。  
在统一项目里，它是壳与变现层，不是可删的附录：演示脚本以大厅开始、以大厅领战令结束。

真实 SDK 仍用 **接口层 + Mock** 还原时序即可。

---

## 3. 范围

### 必做

1. **公会系统（客户端）**  
   - 创建公会、邀请（假数据）、成员列表、公会「奇观/建筑」展示页  
2. **商城**  
   - 商品列表、页签、购买（扣假货币）、购买成功刷新  
3. **战令**  
   - 等级进度、免费/付费轨奖励、一键领取  
4. **活动中心**  
   - 活动列表、打开某活动页、配置化入口（模拟 Pandora 容器）  
5. **协议与缓存层**  
   - 登录下发静态表；打开 UI 拉动态；本地 cache；推送 invalidate  

### 可做

- 拍卖行：上架/搜索/购买的假流程  
- 「充值」：调 `IMidasService::Pay` Mock，成功发货回调  

### 不做

- 真 QQ/微信登录、真支付、真运营后台  
- 公会战玩法、大型社交 IM

## 5. 数据流设计（简历话术核心）

### 5.1 三种数据

| 类型 | 时机 | 例子 | 缓存 |
|------|------|------|------|
| 静态初始化 | 登录进游戏 | 商品表、战令档位配置、活动入口配置 | 内存 + 可选本地 | 
| 动态请求 | 打开某 UI | 成员在线状态、战令个人进度、限购剩余 | 按 UI 域缓存 |
| 推送同步 | 服务器变更 | 购买成功、战令升级、公会成员变动 | 更新 cache 并通知 UI |

### 5.2 时序

```
Login
  → C2S_GetStaticBundle
  → 存入 ClientDataStore（只读表）

OpenShop
  → 若 cache 未过期：直接填 UI
  → 否则 C2S_GetShopDynamic → 填 UI → 写 cache(ttl=60s)

Buy
  → C2S_Buy(itemId, count)
  → S2C_BuyResult
      → 成功：扣货币、改限购、刷 UI、打点日志
      → 失败：错误码 Toast

ServerPush_CurrencyChanged
  → DataStore 更新 → 货币栏监听刷新
```

### 5.3 Proto 风格约定（可用 UStruct 模拟）

不必上真 Protobuf；用同名 UStruct + 注释「对应 proto」即可。

```
Msg_StaticShopConfig
Msg_ShopDynamicState
Msg_BuyReq / Msg_BuyAck
Msg_GuildInfo / Msg_GuildMemberList
Msg_BattlePassConfig / Msg_BattlePassPlayerState
Msg_ClaimBattlePassRewardReq/Ack
Msg_ActivityList
```

面试句式：  
**「与后端先定 proto；进游戏拉固定配置；开 UI 拉动态；本地缓存；推送驱动脏标记。」**

## 6. 公会（客户端功能说明）

| 功能 | 规则 |
|------|------|
| 创建 | 输入名称 → 花一笔货币 → 成为会长 |
| 成员列表 | 显示昵称、职位、上周贡献（Mock） |
| 邀请 | 从好友假列表选人 → 发送邀请状态 |
| 奇观 | 3 个建筑图标，等级来自 GuildInfo；点击弹出说明 |

权限：普通成员不可解散；会长可「假解散」。  
数据：`GuildSubsystem` 持有 `FGuildInfo` 与成员数组。

---

## 7. 商城

| 规则 | 说明 |
|------|------|
| 货币 | Gold（玩法）、Diamond（充值货） |
| 限购 | Daily / Weekly / Forever |
| 预览 | 点击商品 → 3D/2D 预览位（可用一个 SceneCapture 或静态图） |
| 购买 | Server Mock 校验货币与限购 |

商品预览呼应简历「商品预览系统」：哪怕只是切一张大图 + 模型旋转占位，也要有独立 `ItemPreviewWidget`。

---

## 8. 战令

- 赛季经验：用 Debug 键 `AddBPExp 100` 或完成 Demo04 任务加经验  
- 轨道：Free / Premium；Premium 用「假解锁」按钮模拟付费  
- 领取：单格领取 + 一键领取；已领状态存 PlayerDynamic

## 9. 活动与 SDK 抽象

```
ILoginService      → MockLogin（QQ/微信按钮只切账号名）
IPayService        → MockMidasPay（延迟 0.5s 成功回调）
IActivityContainer → MockPandora（打开活动页加载本地 WBP）
IGroupService      → MockGroup（显示「已加入群」状态）
```

真实项目替换实现即可；Demo 证明你懂 **接入层与业务层分离**。

## 12. 验收清单

- [ ] 登录后不开商城也能拿到静态商品配置  
- [ ] 打开商城才请求动态限购；短时间重开走缓存  
- [ ] 购买成功与失败都有明确 UI 反馈  
- [ ] 战令领取状态正确，不能重复领  
- [ ] 公会三页可切换，数据来自 Mock 协议而非 Widget 写死  
- [ ] 能画板上讲清：静态 / 动态 / 推送 三线数据流  
- [ ] SDK 以接口 + Mock 演示登录/支付回调时序
