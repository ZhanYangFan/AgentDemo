## 1. 一句话定位

「战利品 → 背包 → 制造 → 装配 → 存盘 → 重进读盘」的权威服数据闭环，挂在统一主线上，而不是单独沙盒。

---

## 2. 玩法目标

在统一主线中玩家会反复：

1. 击杀/开箱获得材料（服务环 1～3 与制造）  
2. 背包整理、使用药剂  
3. 铁匠处制造并装配，为矿洞 Boss 做准备  
4. 任意时刻杀进程重进，进度仍在  

不再单独设计「与主线无关的掉落沙盒关」。

## 3. 系统范围

### 必做

| 系统 | 范围 |
|------|------|
| 道具定义 | 静态配置（Id、类型、堆叠、图标、是否唯一实例） |
| 背包 | 格子容量、堆叠、拆分、丢弃、使用 |
| 装备实例 | 每件装备有实例 Guid + 随机/固定词条属性 |
| 装备槽 | 武器 / 头盔 / 胸甲 / 饰品（4 槽即可） |
| 制造 | 配方 + 材料扣除 + 权限判断（仅 Server）+ 产出实例 |
| 存盘 | Server 将背包与装备实例序列化保存；登录读盘 |
| 同步 | 背包与装备变化复制到 Owner Client；属性变化驱动 ASC |

### 不做

- 交易行、邮件、完整经济、无限仓库
- 复杂打造失败率 UI 动画（可有简单成功率）

## 4. 核心概念模型

```
ItemDefinition（静态，DataAsset/DT）
    ↑ 引用
ItemEntry（背包里的一格：DefId + Count + Optional InstanceId）
    ↑
EquipmentInstance（实例：InstanceId + DefId + RolledStats + Durability…）
    ↑ 装备后
EquipmentSlot（槽位 → InstanceId）
    → 应用到 Character / ASC（Modifier 或 Attribute）
```

**关键原则：**

- **Definition 与 Instance 分离**：材料可堆叠无实例；装备不可堆叠有实例。  
- **所有变更走 Server RPC / Server 函数**：客户端 UI 只发「意图」。  
- **制造权限在 DS**：检查配方、材料、等级/标签，全部 Server 判定。

---

## 5. 详细规则

### 5.1 道具类型

| Type | 堆叠 | 实例 | 示例 |
|------|------|------|------|
| Resource | 是 | 否 | 铁矿、皮革 |
| Consumable | 是 | 否 | 治疗药剂 |
| Equipment | 否 | 是 | 步枪、皮甲 |
| Blueprint | 是 | 否 | 解锁配方用（可选） |

### 5.2 背包规则

- 容量：20 格（可配置）  
- 同 DefId 且无实例 → 堆叠至 MaxStack  
- 满包时拾取失败并提示  
- 使用消耗品：Server 扣数量 → Apply GE（回血）  
- 丢弃：Server 生成世界拾取物 Actor  

### 5.3 装备属性

装备实例至少包含：

| 字段 | 说明 |
|------|------|
| InstanceId | Guid |
| DefinitionId | 指向静态定义 |
| PrimaryStats | 如 Attack+10, Armor+5 |
| RareAffix | 0～2 条随机词条（制造时 Roll） |

装配时：

1. 卸下旧装备 → 移除其 Attribute/GE  
2. 放入新装备 → 应用新 GE_Infinite（Asset Tags 标记来源）  
3. 若为武器 → 换 WeaponActor + AbilitySet  

### 5.4 制造流程

```
Client: 点击配方「制造」
  → ServerRPC_Craft(RecipeId)
      → 校验玩家距离制造台
      → 校验配方已解锁
      → 校验材料足够
      → 扣材料（原子操作，失败则回滚）
      → Roll 属性，创建 EquipmentInstance
      → 尝试放入背包；放不下则生成掉落物
      → MarkSaveDirty
      → 复制背包更新到 Owner
```

### 5.5 存盘 / 读盘（简历重点）

**存什么：**

- 背包 Entry 列表  
- 所有 EquipmentInstance  
- 当前装备槽映射  
- （可选）已解锁配方  

**何时存：**

- 制造成功 / 装备变更 / 关卡退出 / 定时 60s  

**读盘时机：**

- 玩家 Controller 具备后、Pawn 生成前或生成后立刻  
- **保证在 DS 上稳定执行**：读盘完成前不处理拾取/制造 RPC（加 Ready 门闩）

**格式建议（Demo 级）：**

- 本地：`SaveGame` 对象，按 PlayerId 分档  
- 进阶：JSON 文件，便于你面试时打开讲解字段  

伪结构：

```json
{
  "playerId": "local-1",
  "inventory": [{"def":"Ore_Iron","count":12}],
  "instances": [{"id":"...","def":"Weapon_Rifle","stats":{"Atk":15}}],
  "slots": {"Weapon":"instance-guid"},
  "recipes": ["Recipe_Rifle_T1"]
}
```

## 6. UI 规格

### 背包界面

- 格子列表、拖拽到槽位、右键使用/丢弃  
- Tooltip：名字、描述、实例属性  

### 装备界面

- 4 槽位纸娃娃（可用简单图标位）  
- 总属性预览（汇总 Attack/Armor）  

### 制造界面

- 左侧配方列表，右侧材料需求（红/绿表示是否足够）  
- 制造按钮；成功飘字 + 背包刷新  

**UI 原则（简历话术）：**  
UI 只读「本地已同步的 InventoryView 模型」，不自己算权威结果；Server 拒绝时要有错误码提示。

```
Inventory/
  ItemDefinition.h          // PrimaryDataAsset
  InventoryComponent.h      // 挂 PlayerState 或 Controller
  InventoryTypes.h          // FItemEntry 等

  EquipmentInstance.h
  EquipmentManagerComponent.h   // 槽位、装配、FastArray 可选用
Crafting/
  CraftingRecipe.h          // DataAsset
  CraftingStationActor.h
  CraftingComponent.h
Persistence/
  PlayerSaveSubsystem.h
  PlayerSaveData.h          // USaveGame
UI/
  WBP_Inventory / Equipment / Crafting
```

复制建议：

- `FFastArraySerializer` 做背包或装备列表（面试能提 Lyra Inventory 思路即可）  
- 或简化：整包 `InventoryComponent` 属性复制 + `RepNotify` 刷 UI
