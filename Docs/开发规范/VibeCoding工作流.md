# Vibe Coding 工作流

> 人负责方向与验收，AI 负责按策划小步实现。本文件教你「怎么开发」。

---

## 1. 角色分工

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| 你 | 选当前 VS、定取舍、跑编辑器验收、面试口述 | 让 AI 一次性写完全部系统 |
| Cursor Agent | 读规范 → 改指定范围 → 对照验收 | 擅自改策划范围、横铺半成品 |

---

## 2. 一次标准会话流程

```
1. 打开 AGENTS.md + 当前模块策划案
2. 用「标准话术」发任务（目标/范围/依据/验收/不要做）
3. AI 先读相关文件，再改代码
4. 编译 / 进 PIE 按验收清单勾选
5. 通过则标记 VS；不通过只修失败项，不顺手加功能
```

---

## 3. 推荐提示词模板

### 实现新功能

```
按 VS3 做背包拾取堆叠。
只改 Source/AgentDemo/Inventory/。
依据：Docs/策划案/03 §5.2、GDD §6.2。
验收：Server 可堆叠；Client RPC 伪造无效。
不要做：制造、拍卖、UI 美化。
```

### 修 bug

```
Bug：交任务后奖励没进背包。
先定位 RewardService → Inventory 调用链，再最小修复。
不要重构任务系统。
```

### 解释 / 复习（面试用）

```
根据当前代码，用面试口述模板讲清装备 Instance 与存盘门闩。
只分析，不改代码。
```

---

## 4. 何时开新 Chat

- 切换到另一个 VS（例如从战斗转到背包）  
- 上下文已经很长、Agent 开始忘约束  
- 需要纯规划讨论（先对齐再实现）  

同一 VS 内的连续修 bug 可留在同一会话。

---

## 5. 验收节奏

每个 VS 结束必须有：

1. 可演示的玩法结果（不是「代码写了」）  
2. 对应策划案验收清单打勾  
3. 你能按总纲「面试口述模板」讲 3～5 分钟  

---

## 6. 文档与代码的关系

| 文档 | 用途 |
|------|------|
| `00` / `06` | 主循环、接口、切片 —— 冲突时以它们为准 |
| `01`～`05` | 模块细则与面试题 |
| `AGENTS.md` + `.cursor/rules/` | 约束 Agent 行为 |
| 代码 | 唯一真相；文档过时就改文档，禁止代码与 GDD 接口各搞一套 |

---
